## Production rollback plan (never execute as part of this rehearsal)
For an actual approved Production rollback of an affected Cloud Run function, verify its current serving revision and known-good revision immediately before a change, then use the documented `gcloud run services update-traffic SERVICE --to-revisions=KNOWN_GOOD_REVISION=100`. This is a **Production write** and requires specific incident/owner approval. Rolling traffic back does not reverse database mutations, Auth claims, Secret versions or external side effects.

The true Production gate remains pending until a real sandbox rehearsal PASS, live Beta smoke evidence, public safety fresh probe, browser App Check, monitoring/billing, PDPA, explicit scoped Production deploy approval and rollback operator validation. A dry-run or offline model alone must never be marked `ROLLBACK_REHEARSAL_PASS`.
