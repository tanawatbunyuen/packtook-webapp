### Phase A. Provision exactly one HMAC Secret and initial version

Prerequisites:
- Owner explicit \`SECRET_ONLY\` authorization and a privacy/security responsible person.
- Confirm the resource is \`NOT_FOUND\` rather than \`PERMISSION_DENIED\`; verify correct GCP project and Secret Manager API is enabled. If missing API must be enabled, this is **another owner-approved cloud change**, not something the script silently does.
- Confirm source HMAC validation: \`/^[A-Fa-f0-9]{64}$/\` and persistence design \`publicSignupGuards/email_v1_*\`. Once that HMAC key has been used, rotation without migration can undermine cross-UID/regrant controls. Never regenerate/reprovision existing key.
- Prefer to generate 32 cryptographically random bytes with the system secure RNG and encode as 64 hex. **Never print key to a terminal, pass it as a CLI argument or store in GitHub, chat, \`.env\`, command history or persistent file.**

**Change-operator example, for separate approval ONLY (do not run during read-only preflight):**

\`\`\`bash
# DO NOT RUN until a separate SECRET_ONLY Production change is approved.
# Uses an ephemeral anonymous pipe: no plaintext secret in CLI argv or shell history.
set -euo pipefail
PROJECT="packtook-prod-01"
SECRET="PACKTOOK_PUBLIC_FREE_EMAIL_HMAC_KEY_HEX"

# Inspect the EXACT Secret; treat 403/timeouts as HALT, not NOT_FOUND.
if RESPONSE=$(gcloud secrets describe "$SECRET" --project="$PROJECT" \
  --format="value(name)" 2>&1); then
  echo "HALT: Secret already exists; do not overwrite or rotate."
  exit 2
else
  case "$RESPONSE" in
    *NOT_FOUND*|*"not found"*) echo "PASS: Secret absent, create-only path eligible" ;;
    *) echo "HALT: Secret existence unclear; owner must investigate permissions"; exit 2 ;;
  esac
fi

# After separate SECRET_ONLY owner approval + exact reviewed NOT_FOUND:
# 32 random bytes => 64 ASCII hex, transferred over stdin, never displayed.
python3 -c 'import secrets,sys;sys.stdout.write(secrets.token_hex(32))' |
  gcloud secrets create "$SECRET" --project="$PROJECT" \
    --replication-policy=automatic --data-file=-
\`\`\`

**Important:** This is a human-reviewed, explicitly approved operator recipe. The guard exits on an existing Secret or ambiguous 403/timeout before the create step; \`gcloud secrets create\` itself also refuses an existing name. The pipeline's key is generated in memory and is not printed, but authorized operators must still review Cloud Shell session security, replication policy, billing and secret retention. No secrets are output back to ChatGPT.

Verify afterward **using metadata only**:
