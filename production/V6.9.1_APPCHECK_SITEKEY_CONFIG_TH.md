# PACKTOOK V6.9.1 — ตั้งค่า reCAPTCHA Enterprise Site Key บน GitHub (ปลอดภัย)

## อัปเดต 2 พ.ย. 2026 — Site Key แบบเต็มเพิ่มลง GitHub แล้ว

ได้รับ **PUBLIC reCAPTCHA Enterprise Web Site Key ฉบับเต็ม** จากเจ้าของระบบแล้ว และบันทึกที่ `app/signup-config.js` บน Branch V6.9.1 โดยไม่เผยข้อมูลอื่นหรือเปลี่ยนสิทธิ์ของ Production. ขั้นตอนการใช้ `set-appcheck-site-key.mjs` ด้านล่างใช้สำหรับกรณีต้องกำหนด Key บนเครื่องใหม่เท่านั้น **ไม่ต้องทำซ้ำ** หากดึง Branch ปัจจุบันมาแล้ว.

ผลตรวจซอร์สโค้ด:
- Format Validation: **PASS** (ความยาว 40 ตัวอักษร)
- `check-appcheck-readiness`: **A07 = manual** (Site Key มีแล้ว แต่ Console + Token จริงยังไม่ยืนยัน), **A08 = blocked** (Terms/Privacy รออนุมัติ)
- `public-launch-preflight`: B01 App Check Source = **pass**, Public Go-Live = **NO**
- **ยังไม่มี Firebase Hosting Deploy** ในการแก้ไขนี้. Browser ที่ Production ยังไม่ถูกยืนยันว่าโหลด Site Key ล่าสุด
- Google Cloud reCAPTCHA Key Details ก่อนหน้านี้ขึ้น **Incomplete**; ต้องตรวจ Key status, การอนุญาตโดเมน และการสร้าง Token ใน Browser จริง

หลังดึง Branch ล่าสุด:

```bash
cd ~/packtook-production-v621
git fetch origin feature/v6.9.1-appcheck-site-key-integration
git switch feature/v6.9.1-appcheck-site-key-integration
git merge --ff-only FETCH_HEAD
cd production
node scripts/test-appcheck-sitekey-configuration.mjs
node scripts/test-appcheck-readiness.mjs
node scripts/test-onboarding-ui.mjs
node scripts/test-public-launch-preflight.mjs
node scripts/check-appcheck-readiness.mjs --json
```

**ขอบเขต:** ยังไม่ Deploy, ไม่เปิด Public Signup/Access, ไม่เปลี่ยน `completeFreeSignup`, ไม่เปิด Global App Check enforcement และไม่เปิด Omise Live. การ Deploy Customer-only เพื่อทดสอบ Token จริงเป็นขั้นตอนแยกที่ต้องทดสอบ Beta Regression และยืนยันเป้าหมายก่อนดำเนินการ


**สถานะ:** Firebase App Check หน้า Apps แสดง Web App **PACKTOOK Production Customer** เป็น **Registered** และผู้ใช้เปิด Google Cloud reCAPTCHA Enterprise Key ชื่อ `PACKTOOK-PROD-WEB` สำหรับโดเมน `packtook-prod-01-app.web.app` แล้ว

**สถานะล่าสุด:** Site Key แบบเต็มได้รับจากเจ้าของและ Commit แล้ว; แต่ภาพเดิมแสดง **Incomplete** และยังไม่ได้ยืนยัน Browser Token จริง จึงยังไม่เปิด Public

## สิ่งที่ทำใน V6.9.1

- อัปเดต `app/signup-config.js` ด้วย PUBLIC Site Key แบบเต็มที่เจ้าของส่งมาแล้ว; การตั้งค่าไม่ได้เปิด Public ด้วยตัวเอง
- เพิ่ม `scripts/set-appcheck-site-key.mjs` สำหรับใส่ PUBLIC SITE KEY แบบเต็ม โดยแก้เฉพาะคีย์เดียวและปฏิเสธ key ที่มี `...`, มีอักขระผิด, สั้นเกินไป หรือมีค่าเดิมต่างกัน
- เพิ่ม `scripts/test-appcheck-sitekey-configuration.mjs` ตรวจการป้องกัน, key ตัวอย่าง, UI/server safety
- ปรับ Regression Tests ของ V6.5, V6.6 และ V6.9 ให้ใช้ได้ทั้งก่อนและหลังตั้ง Site Key ไม่ทำให้เทสต์ที่ดีแล้วล้มเพราะค่าไม่ว่าง
- เพิ่ม Regression Test ลงใน `deploy-promptpay-customer.sh` โดยยัง Deploy ได้เฉพาะ `hosting:app` เท่านั้น

## ก่อนใส่ Key

1. ไปที่ <https://console.cloud.google.com/security/recaptcha> ภายใต้โปรเจกต์ `packtook-prod-01`
2. เปิด Key details ของ `PACKTOOK-PROD-WEB` ตรวจว่าเป็น **Web / score-based**, และอนุญาตโดเมน `packtook-prod-01-app.web.app` โดยไม่เพิ่ม localhost ใน Production
3. ตรวจความหมายของป้าย **Incomplete** และทำขั้นตอนที่ Cloud Console แจ้งให้ครบ Key ต้องไม่อยู่ในสภาพผิดพลาด
4. คลิกไอคอน Copy ข้าง **ID** เพื่อคัดลอก Site Key เต็ม (ไม่ใช่ Secret/API Key)

## วิธีใส่ Site Key แบบไม่บันทึกไว้ใน Shell History

```bash
cd ~/packtook-production-v621
git status --short
git fetch origin feature/v6.9.1-appcheck-site-key-integration
git switch feature/v6.9.1-appcheck-site-key-integration 2>/dev/null || \
git switch -c feature/v6.9.1-appcheck-site-key-integration FETCH_HEAD
git merge --ff-only FETCH_HEAD
cd production

# Key เป็น Public Site Key แต่ไม่ควรใส่ลงในประวัติคำสั่ง
read -r -p "Paste FULL reCAPTCHA Enterprise Web Site Key: " PACKTOOK_RECAPTCHA_SITE_KEY
export PACKTOOK_RECAPTCHA_SITE_KEY
node scripts/set-appcheck-site-key.mjs --apply
unset PACKTOOK_RECAPTCHA_SITE_KEY

node scripts/test-appcheck-sitekey-configuration.mjs
node scripts/test-onboarding-ui.mjs
node scripts/test-public-launch-preflight.mjs
node scripts/test-appcheck-readiness.mjs
node scripts/check-appcheck-readiness.mjs --json
```

หากทุก Test ผ่านให้ Commit/PUSH เพียงไฟล์ Configuration นี้ขึ้น GitHub Branch:

```bash
git add app/signup-config.js
git commit -m "V6.9.1: configure production public reCAPTCHA Enterprise Web Site Key"
git push origin feature/v6.9.1-appcheck-site-key-integration
```

Site Key นี้เป็นค่าสำหรับการทำงานของ Browser จึงไม่ใช่ Secret แต่ต้องเป็นค่าเต็มและตรงกับ Site Key ใน Firebase App Check. **อย่า Commit Service Account, Omise Secret, Firebase secret, Debug Token หรือข้อมูลลูกค้า**

## การ Deploy และทดสอบจริง (ขั้นถัดไป — ไม่ทำอัตโนมัติ)

- หลังเจ้าของตรวจผลจริงและอนุญาต Deploy ให้ใช้การ Deploy **Customer Hosting เท่านั้น** พร้อม Regression Tests
- ตรวจ Browser Developer Tools / Firebase App Check Metrics ว่าส่ง App Check Token ได้จริง
- ปัจจุบัน Backend `completeFreeSignup` ยังไม่ได้ยืนยันว่าถูก Deploy; การรับ App Check Token จาก Browser อย่างเดียวไม่ใช่หลักฐานว่า Free สมัครได้จริง
- **อย่าเปิด Enforce แบบครอบจักรวาล** กับบริการ Beta; `completeFreeSignup` มี `enforceAppCheck:true` ในซอร์ส แต่ต้องทดสอบฟังก์ชันจริงอย่างควบคุม
- `PACKTOOK_PUBLIC_SIGNUP_ENABLED=false`, `PACKTOOK_PUBLIC_ACCESS_ENABLED=false` และ `PACKTOOK_PUBLIC_POLICIES_APPROVED=false` คงเดิม
- Terms/Privacy ยังเป็นร่าง, Marketing ยัง Prelaunch/noindex, Omise Live ยังคงปิด
