## Step 3 — validate the Functions environment BEFORE status-only deployment

The existing read-only `publicSignupStatus` backend is protected by a guard that requires `PACKTOOK_PRODUCTION_PROJECT_ID` and the 3 independent Public rollout flags. The targeted deployment script **refuses to run** without explicitly verifiable FALSE values, never silently modifies or overwrites existing env files.

```bash
node scripts/check-public-status-rollout.mjs packtook-prod-01
```

The preflight reads only `functions/.env` and `functions/.env.packtook-prod-01`, prints **only safe flag names** and checks:
- `PACKTOOK_PRODUCTION_PROJECT_ID=packtook-prod-01`
- `PACKTOOK_PUBLIC_SIGNUP_ENABLED=false`
- `PACKTOOK_PUBLIC_ACCESS_ENABLED=false`
- `PACKTOOK_PUBLIC_POLICIES_APPROVED=false`

If the preflight reports a missing configuration, **do not deploy**. Review which of these files already exists without printing their other secret values:

```bash
ls -l functions/.env functions/.env.packtook-prod-01 2>/dev/null || true
```

When the project-specific file does **not** exist, the operator may create it with *only those four nonsecret settings*, after checking that no generic `functions/.env` contains conflicting settings:

```bash
if [ ! -e functions/.env.packtook-prod-01 ]; then
  cat > functions/.env.packtook-prod-01 <<'ENV'
PACKTOOK_PRODUCTION_PROJECT_ID=packtook-prod-01
PACKTOOK_PUBLIC_SIGNUP_ENABLED=false
PACKTOOK_PUBLIC_ACCESS_ENABLED=false
PACKTOOK_PUBLIC_POLICIES_APPROVED=false
ENV
fi
node scripts/check-public-status-rollout.mjs packtook-prod-01
```

**If the file already exists, never overwrite it automatically.** Review and reconcile safely, preserve other configuration, and rerun the preflight. Note that Firebase Functions CLI loads project-specific and generic env files. Do not commit any env file that contains credentials.
