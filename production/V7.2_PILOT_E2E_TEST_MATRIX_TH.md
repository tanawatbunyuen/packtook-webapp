## Testing discipline

Every row needs a tester, timestamp, release SHA, observed result, test category and PASS/FAIL evidence retained in a **private, access-controlled** release record. Do not put test UID, email, password, App Check token, secret, full video or screenshots of private data into a GitHub PR or ChatGPT.

When running real QA in a future approved window:
- Exact Customer App Check ID must be verified server side; token verified by actual callable transport, **not a stub**.
- Pilot users must be owner-invited/pre-provisioned. A website hiding a button does not control access.
- Distinguish expected **block** cases from failures. Any authorization escape is a P0 incident.
- All Public flags must stay OFF, Omise Live OFF, Marketing CTA hidden, QA invite OFF.
- Record full rollback/revocation outcome and Beta smoke while the Pilot is enabled, after expiry and after kill switch.
