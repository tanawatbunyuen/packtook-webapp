## Server-side kill switches — ALL OFF by default

Do not set these in Production until an approved release gate:
- PACKTOOK_PUBLIC_SIGNUP_ENABLED=true
- PACKTOOK_PUBLIC_ACCESS_ENABLED=true
- PACKTOOK_PUBLIC_POLICIES_APPROVED=true

All three flags must be true and PROJECT ID must match the locked Production ID. Existing Beta claim remains valid irrespective of public signup flags. All public sessions can be denied with PUBLIC_ACCESS_ENABLED=false.

**App Check:** completeFreeSignup has enforceAppCheck:true and checks req.app.appId. app/signup-config.js intentionally uses appCheckSiteKey: "". Before QA registration enablement, configure a valid reCAPTCHA Enterprise site key for the intended authorized domain; App Check keys are public, NEVER use a secret key in HTML.

**Terms/Privacy:** POLICY_VERSION=2026-11-v1 must match Backend, Customer and reviewed legal pages. Current pages are draft. Never set PACKTOOK_PUBLIC_POLICIES_APPROVED=true while they are unapproved.

**Safety:** Firestore client access remains denied by security rules, Auth custom claim and Free credit are written only through Backend/Admin SDK, and reactivation cannot reset credits or paid-plan wallets. Production Payment Functions remain Omise TEST and require a separate Beta Tester claim. New public users CANNOT buy paid plans in V6.5.

## QA scenarios to perform in isolated Firebase Emulator or approved QA environment

1. Public flags OFF: button hidden; function denies signup; Beta customer still records.
2. Public flags ON but App Check site key missing: button remains unavailable; function denies requests without valid App Check.
3. Policies not approved: button hidden, API denies.
4. New customer: register unique email, verification link sent, cannot record before verification and consent.
5. Verified user logs in: confirm consent; Free account created server-side; token refreshed; 20 remaining; add first device.
6. Record and finalize one video: 19 remaining; one device enforced; local file opens.
7. Second activation/relogin: no extra Free credits, no duplicate account, no reset used counter.
8. Wrong version/consent/missing App Check/unverified/disabled account: denied with no Free grant.
9. Existing Beta and paid customers: never overwritten or downgraded.
10. App Check, Cloud Functions, Firestore transaction and claim-update-failure recovery in a real QA environment.
11. Payment: new public account cannot create a paid QR; Omise LIVE never enabled.
12. Incident: disabling PUBLIC_ACCESS should block public sessions without affecting Beta accounts.

**Source/mock tests are not Firebase Auth/Email/App Check/Browser integration tests.** Do not mark V6.5 production acceptance passed until QA items are exercised in an isolated environment.
