# PACKTOOK V6.2.3 — Owner Customer Management (Production Beta)

**Project**: `packtook-prod-01`  
**Branch**: `feature/v6.2.3-owner-customer-management`  
**Status**: Code committed with local mock/transaction regression tests. **Not deployed by the assistant.** Customer V6.1.2 remains unchanged.

## Scope

- Adds "จัดการ" for each Customer in the Owner Dashboard, guarded by separate Owner Manager role.
- Action 1: add **1–500 video credits** to a customer who ALREADY has `creditWalletV1:true`, finite-credit active plan and zero reserved credits.
- Action 2: correct/set **future subscription expiration** for existing paid-plan customers only (Free plan has no expiry). Supports paid accounts whose existing expiration is missing, in order to correct that data.
- Frontend requires reason (10–300 characters), retyping the customer's email, browser confirmation, and a unique UUID operation ID.
- Backend checks the current Production Firebase Auth Owner identity, `packtookPlatformOwner`, separate `packtookOwnerManager` claim, and `PACKTOOK_OWNER_MANAGEMENT_ENABLED=true`.
- Firestore transaction checks the original displayed balance/expiration/plan/reserved amount, and requires no pending reservations or billing request.
- Each approved change atomically updates the customer account and creates records under `accounts/{uid}/ownerChanges/{operationId}` and `accounts/{uid}/audit/owner_{operationId}`.
- Duplicate requests with matching UUID and payload are **idempotent**, never double-grant credits. A reused UUID with differing payload is rejected. Audit history (latest 20 actions) is displayed on the Owner page.
- No `billingRequests` document, payment action or Live Omise charge is created.

### Important limitation: Free monthly quota

**Do not silently convert a Free account (20 videos/month) to an everlasting credit wallet.** For that reason, this release intentionally rejects extra-credit grants for legacy monthly accounts where `creditWalletV1` is not true. Such customers will show the reason and the grant control is disabled. A later reviewed Customer Backend update will be required to support bonus credits for Free without changing monthly reset behavior.

Paid customer plan creation/upgrading is **not** part of this release. You can adjust expiration for an EXISTING paid plan, but not assign Starter/Pro via Owner Management.

## B. Prepare with management **disabled**

```bash
bash scripts/prepare-owner.sh packtook-prod-01

cat owner-functions/.env.packtook-prod-01
```

The local env file should have `PACKTOOK_PRODUCTION_PROJECT_ID=packtook-prod-01`. Without `PACKTOOK_OWNER_MANAGEMENT_ENABLED=true`, management is fail-closed.

Deploy ONLY the Owner codebase:

```bash
bash scripts/deploy-owner-functions.sh packtook-prod-01
```

Type `DEPLOY-PROD-OWNER-FUNCTIONS`.

Then deploy ONLY Owner Hosting:

```bash
bash scripts/deploy-owner-hosting.sh packtook-prod-01
```

Type `DEPLOY-PROD-OWNER-HOSTING`.

Owner page: https://packtook-prod-01-owner.web.app/

At this stage the existing Owner Analytics and Revenue Charts should continue working, and the management status should show **read-only** (this is deliberate).

## C. Explicitly activate Owner Management (only after the initial checks)

Using **one verified Production Platform Owner Auth UID** from Firebase Console:

```bash
cd ~/packtook-production-v621/production
export GOOGLE_CLOUD_PROJECT=packtook-prod-01

node owner-functions/scripts/manage-owner-manager.js grant PRODUCTION_OWNER_UID

bash scripts/set-owner-management.sh packtook-prod-01 enable
```

At the second command prompt type `ENABLE-PROD-OWNER-MANAGEMENT`.

**Apply the environment change**:

```bash
bash scripts/deploy-owner-functions.sh packtook-prod-01
```

Confirm `DEPLOY-PROD-OWNER-FUNCTIONS`. No additional Hosting deployment needed for the flag. Sign out/in of Owner to refresh its custom claims (Firebase docs: https://firebase.google.com/docs/auth/admin/custom-claims).

Both requirements must be met to perform mutations: Owner + Owner Manager custom claims **and** environment flag enabled.

## D. Disable / rollback the mutation feature immediately

```bash
bash scripts/set-owner-management.sh packtook-prod-01 disable
bash scripts/deploy-owner-functions.sh packtook-prod-01
```

Optionally revoke the extra manager claim:

```bash
node owner-functions/scripts/manage-owner-manager.js revoke PRODUCTION_OWNER_UID
```

The Owner Analytics and charts still work while management is disabled.
