# PACKTOOK V6.7 — Free Public Launch Integration QA

**Branch:** `feature/v6.7-free-emulator-integration-qa` (based on V6.6)
**Scope:** Test harness / release evidence only. **NOT DEPLOYED. PUBLIC FREE OFF. OMISE TEST ONLY.**

## สิ่งที่เพิ่มใน V6.7

- `scripts/test-free-auth-firestore-emulator.mjs`: execute the REAL backend signup / credit / device function bodies against **real Firebase Auth Emulator + Firestore Emulator** using Firebase Admin SDK; callable transport is stubbed.
- `scripts/run-v67-emulators.sh`: guarded emulator-only runner with **demo-packtook-v67** fixed project; no Firebase deploy or live resources.
- `scripts/test-v67-emulator-safety.mjs`: proves the harness refuses to run without both loopback emulators and demo-only opt-in or if live production project environment leaks in.
- `scripts/probe-free-deployment.mjs`: read-only live check of Marketing Hosting, Customer Hosting, and `publicSignupStatus` Callable with flags. Can identify missing deployment of Customer V6.6.
- `scripts/test-free-deployment-probe.mjs`: offline tests for the read-only probe and detection of accidentally enabled Public flags.

## Strict limitations

1. The emulator integration tests **real Firebase Auth + Firestore emulator** CRUD, transactions and custom claims. They do **not** test the actual Cloud Functions HTTP callable transport or cryptographic App Check attestation. The test injects a simulated `req.app.appId` after checking production source contains `enforceAppCheck:true`.
2. Emulators do **not** test sending actual Firebase Auth verification emails. Use a separate approved account/browser test for this.
3. They do **not** produce or play a real packing video. Customer browser/video acceptance remains required.
4. They do **not** test PDPA approvals, tax/payment terms or real Omise LIVE.
5. All production flags `PACKTOOK_PUBLIC_SIGNUP_ENABLED`, `PACKTOOK_PUBLIC_ACCESS_ENABLED`, `PACKTOOK_PUBLIC_POLICIES_APPROVED` must stay **OFF** until owner go-live approval.
6. In particular, use a **demo- project** rather than a real Firebase project during emulator testing. Firebase recommends demo projects because un-emulated APIs cannot silently contact live resources.

## Run real Auth + Firestore emulator integration (still no deploy)

```bash
cd ~/packtook-production-v621/production

# These dependencies are local tooling, not additional Firebase accounts:
test -d functions/node_modules/firebase-admin || npm ci --prefix functions

# This is DEMO-ONLY and has a hard safety guard:
bash scripts/run-v67-emulators.sh --demo-only
```

If the Firestore emulator needs Java / a downloaded runtime, follow Firebase Emulator CLI messages. You may see progress while the emulator downloads Java libraries. The test only writes generated QA user IDs into the in-memory/local demo emulator, and cleans them afterwards.

**Expected emulator test stages:**
- Public disabled: cannot create a Firestore account
- No App Check request field / unverified Auth email / missing consent: rejected by actual handler body
- Verified demo user + valid consent: one account with Free 20 videos and custom Auth claim
- First registered device allowed; second device rejected
- Reserve one video: 19 remaining, 1 reserved
- Finalize video: 19 remaining, 1 used, 0 reserved
- Duplicate finalize and reactivation: no extra credit debit or grant
- Disabled Auth user cannot reactivate

This does **not** mean App Check cryptographic attestation or the real browser has been tested. Both remain Public-launch blockers until verified.

## Read-only live deployment probe

```bash
node scripts/probe-free-deployment.mjs packtook-prod-01 --expect-v66
```

The live probe checks `https://packtook-prod-01-app.web.app/`, Marketing HTML and the read-only `publicSignupStatus` Callable. It performs no Auth signup or Firestore writes.

- `CUSTOMER_V66_NOT_DEPLOYED` means Customer Hosting has not served the V6.6 JS source reference yet.
- `CUSTOMER_SIGNUP_HTML_NOT_DEPLOYED` means the public form/verification step are absent from served HTML.
- `PUBLIC_STATUS_CALLABLE_NOT_DEPLOYED_OR_UNVERIFIED` means check the Backend release/permissions/region; no assumption that it is deployed.
- `UNEXPECTED_PUBLIC_FLAG_ENABLED` is a safety alert. Do not proceed until the real Backend configuration is audited.
- If everything is reachable and flags false, it only certifies read-only deployment visibility, not an authorized Public launch.
