### Gate 2 — Firebase reCAPTCHA Enterprise App Check (MANUAL CONSOLE)

Official: https://firebase.google.com/docs/app-check/web/recaptcha-enterprise-provider

1. Firebase project **packtook-prod-01** → verify correct Web App ID used by `app/firebase-v4-config.js` on Customer Hosting. Do not copy a Staging config.
2. Google Cloud reCAPTCHA Enterprise → create a **score-based Web key** restricted to actual Customer app domain `packtook-prod-01-app.web.app` (and explicitly approved future custom domains). Never register localhost on a Production reCAPTCHA key. No checkbox challenges.
3. Firebase Console → Security → App Check → register that **exact Web App** with reCAPTCHA Enterprise Web Site Key. Record the key ID, authorized domains, registration and App Check metrics.
4. Insert **only public Site Key** into `production/app/signup-config.js` on a reviewed branch. **Never commit a private API secret, GCP credentials or debug token**.
5. Validate `ReCaptchaEnterpriseProvider` starts and attaches token to callable requests on the intended Customer domain. Confirm missing/invalid token is rejected by **deployed** `completeFreeSignup` (`enforceAppCheck:true`). Existing Beta users must remain functional.
6. The Client App Check Site Key alone MUST NOT turn on the public rollout; Backend remains authoritative, default flags OFF.

App Check is an app attestation layer, not a replacement for Auth, email verification, Firestore rules, anti-abuse checks, or legal consent. Do not turn on blanket Firebase Auth/Firestore App Check enforcement without investigating effects on the existing Beta service first.
