# PACKTOOK V6.3 — PromptPay QR Payment ONLY (Omise TEST)

**GitHub branch:** `feature/v6.3-promptpay-qr-test`  
**Firebase:** `packtook-prod-01`  
**Status:** Source code and mocked integration test complete. **Nothing has been deployed by this branch yet.**  
**Live payments:** DISABLED. **Credit card:** NOT IMPLEMENTED (future separate release).

## Scope

- Reuses PACKTOOK Customer UI/Packing/Dashboard from production V6.1.2 and Owner V6.2.3 without changing their existing core Functions.
- Uses dedicated Firebase Functions codebase `promptpay`: 10 scoped endpoints — subscription overview/history, request, cancel, test config, create PromptPay Charge, recover, poll, signed webhook, audit.
- Purchase request created without changing account balance or plan. Only a verified Production Beta user with **explicit `packtookPaymentTester:true` custom claim** may create or settle a test payment from the customer UI; ordinary Beta customers cannot buy in Test Mode.
- Only `source[type]=promptpay` is ever submitted to Omise.
- Charge uses an **Omise Test Secret Key** starting `skey_test_`, explicit project and enabled flag, short (30-minute) QR expiry, and `ref_id` to mitigate duplicate charges.
- QR image URL is obtained from `charge.source.scannable_code.image.download_uri` and displayed only from `https://api.omise.co`.
- A signed `charge.complete` / `charge.update` webhook triggers an **independent** GET of the charge from Omise and validates account ID, request ID, charge ID, amount, THB, PromptPay source type, `livemode=false`, and `paid=true` with `status=successful` before settling a purchase.
- Firestore Transaction makes a successful purchase idempotent: 30-day plan, credits added/retained, expiry, and audit log are updated atomically. The pending QR does **not** upgrade an account.
- The customer can manually recheck its charge, or recover an uncertain charge creation through controlled Omise lookup.
- The per-Charge **dynamic webhook** points only to the Production endpoint. It does not overwrite the Omise account's single static webhook that Staging may already use.
- Payments and the customer test balance can be simulated using the Omise Test Dashboard; no money is deposited.
- **Known limitation**: Test credits do update the Production test account's plan/wallet after successful simulated payment. Test with a dedicated Beta account, not a customer operating live orders.
- **No card payment**: no card fields or card source are created, no Visa/Mastercard tokens, no card checkout, no live secrets.

## 3. Configure Test-only Omise credentials via Secret Manager

Open the Omise Dashboard in **Test Mode**. Obtain its Test Secret API Key (`skey_test_...`) and its **Base64-encoded Test Webhook Secret** (not a live-mode webhook secret). Never put them into GitHub, frontend JavaScript, chat, or Shell history.

```bash
firebase functions:secrets:set PACKTOOK_OMISE_TEST_SECRET_KEY \
  --project packtook-prod-01

firebase functions:secrets:set PACKTOOK_OMISE_TEST_WEBHOOK_SECRET \
  --project packtook-prod-01
```

Enter each value in the Firebase CLI interactive secret input. The Webhook Secret comes from Omise Test Webhooks Settings, not the Omise Public Key.

**Omise account setup**: PromptPay must be enabled on the merchant account. If the payment source is rejected, contact Omise support about PromptPay activation. See https://docs.omise.co/promptpay .

## 6. Explicitly enable PromptPay QR Test

Only after source checks, secrets, and initial pages pass, first select a dedicated verified **Production Beta test customer** from Firebase Authentication and grant the separately scoped QR Test claim (do not use the Owner account or a customer packing real orders):

```bash
export GOOGLE_CLOUD_PROJECT=packtook-prod-01
node payment-functions/scripts/manage-qr-tester.js grant YOUR_PRODUCTION_BETA_TEST_UID
```

After this command, log out and sign in again to refresh the Firebase ID token. `manage-qr-tester.js` rejects Owner users and non-Beta customers. Without the claim, purchase buttons remain disabled even if the Test environment flag is enabled.

Then switch the backend TEST flag on:

```bash
bash scripts/set-promptpay-test.sh packtook-prod-01 enable
bash scripts/deploy-promptpay-functions.sh packtook-prod-01
```

At the prompts type `ENABLE-PROD-QR-TEST` then `DEPLOY-PROD-QR-TEST-FUNCTIONS`.

Refresh Customer App and sign in to a **verified internal Production Beta account with `packtookPaymentTester:true`**. Packages should now show **ทดลอง PromptPay QR** on an eligible paid plan. There is no credit card choice.

## 7. End-to-end Omise Test checklist

1. Before payment, note the Production Beta test user's plan, credits, expiry.
2. Choose a paid plan (Starter ฿199 or another approved tier); confirm the request, then click `PromptPay QR (Test)`.
3. Check QR image loads from Omise and the status is pending. **Credits and plan must not change yet.**
4. In the Omise Test Dashboard, open that Charge and use **Actions → Mark as Successful**. This simulates payment and must not transfer real funds.
5. The signed Webhook or **ตรวจสถานะ Omise** button independently retrieves the Charge. After successful settlement, verify plan/credits/expiry update exactly once.
6. Repeat **ตรวจสถานะ Omise** several times; there must be no additional credits or expiry extension.
7. Verify a failed/expired simulated charge does not grant credits.
8. Verify wrong/unsigned Webhook request returns 401 and cannot activate any plan.
9. Confirm Owner Revenue Report categorizes this transaction as **Test**, not Live.
10. Verify Customer Camera, Start/Stop Barcode, WebM Saving, Dashboard and one-credit consumption still work.
11. Confirm neither Owner Management nor Staging was changed.

**Webhook delivery is not guaranteed to retry**. Manual Charge Status recheck provides a fallback. When creating a QR fails after external API success but before Firestore linking, use **กู้คืน Charge** rather than creating a new purchase. Avoid cleaning billing tickets by editing Firestore manually.
