# PACKTOOK V6.3.1 — PromptPay Test Authorization Diagnostics

Why V6.3 shows `ยังไม่เปิด PromptPay Test` on all plans: the Customer UI received `enabled !== true` or could not read `promptpayConfig`. The V6.3 UI collapsed three distinct causes into one message:

- Deployed `PACKTOOK_PROMPTPAY_TEST_ENABLED` is false.
- Logged-in Production Beta account is missing `packtookPaymentTester:true` (Owner accounts are not eligible for this customer-only test).
- Firebase Function invocation fails, e.g. authorization/IAM/browser session.

**V6.3.1** safely distinguishes the three states on the Customer Packages page and adds `ตรวจสิทธิ์ QR อีกครั้ง` button. It does not enable live charges or cards.

## Steps

```bash
cd ~/packtook-production-v621
git fetch origin feature/v6.3.1-qr-test-status
git switch -c feature/v6.3.1-qr-test-status FETCH_HEAD
cd production

bash scripts/check-promptpay-test.sh packtook-prod-01
# Optional account diagnosis:
bash scripts/check-promptpay-test.sh packtook-prod-01 ACTUAL_CUSTOMER_BETA_UID
```

The diagnostic is read-only, prints local Test Flag, **deployed** Test Flag, and, when a UID is supplied, verified Email / Beta / QR Tester / Owner booleans. It never displays API secrets. The user's current `gcloud` default project may be Staging; the script explicitly uses `--project=packtook-prod-01`.

## Enable ONLY if local and deployed flag are false

```bash
bash scripts/set-promptpay-test.sh packtook-prod-01 enable
bash scripts/deploy-promptpay-functions.sh packtook-prod-01
```

Type `ENABLE-PROD-QR-TEST` then `DEPLOY-PROD-QR-TEST-FUNCTIONS`. Secret Key must be `skey_test_` and no live payment is possible in this release.

## Grant only a verified Production Beta test account when QR Tester is false

```bash
export GOOGLE_CLOUD_PROJECT=packtook-prod-01
node payment-functions/scripts/manage-qr-tester.js grant ACTUAL_CUSTOMER_BETA_UID
```

The helper checks active, email-verified, `packtookProductionBeta:true`, and not a Platform Owner. Sign out/in of the Customer App after grant to refresh its Firebase ID token.

## Deploy optional V6.3.1 diagnostics interface

```bash
node scripts/verify.mjs packtook-prod-01
node scripts/test-promptpay.mjs
node scripts/test-customer-ui.mjs
bash scripts/deploy-promptpay-functions.sh packtook-prod-01
bash scripts/deploy-promptpay-customer.sh packtook-prod-01
```

Confirm `DEPLOY-PROD-QR-TEST-FUNCTIONS` and `DEPLOY-PROD-QR-TEST-CUSTOMER`. Only PromptPay Functions and Customer Hosting are deployed. Owner and Beta Recording Functions remain unchanged.

In the Customer App, open Packages and click `ตรวจสิทธิ์ QR อีกครั้ง`. It will show one of:
- **Backend ยังปิด ...**: Test env flag false on deployed Functions
- **บัญชีนี้ยังไม่มีสิทธิ์ QR Tester**: claim missing; grant and re-login
- **เชื่อมต่อ Payment Functions ไม่สำเร็จ**: inspect browser console and Firebase function logs
- **PromptPay QR Test พร้อมใช้งาน**: paid plan buttons enabled when purchase eligible

**If the customer is actively recording videos or using a real order workflow, do not use that account for Test purchases.** Test payments can update its real Production credit balance despite transferring no funds.

Rollback:
```bash
bash scripts/set-promptpay-test.sh packtook-prod-01 disable
bash scripts/deploy-promptpay-functions.sh packtook-prod-01
```

Never send keys or paste entire Firebase custom claim contents into chat.
