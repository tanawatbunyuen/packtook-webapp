# PACKTOOK V6.2.3 — ทดสอบเครดิต Wallet โดยไม่แตะบัญชีลูกค้าจริง

**ปัญหาที่พบ:** บัญชี Free ใช้สิทธิ์ 20 วิดีโอต่อเดือน และยังไม่เปิดใช้ `creditWalletV1` จึงถูกบล็อกการเพิ่มเครดิตโดยตั้งใจ เพื่อป้องกันการเปลี่ยนการรีเซ็ตโควตารายเดือนให้กลายเป็น Wallet ถาวร

## วิธีที่ปลอดภัยสำหรับทดสอบ Production

1. ไป Firebase Console ของ **`packtook-prod-01`** → Authentication → Users แล้วสร้างบัญชี **ใหม่** ด้วย Email ที่คุณเป็นเจ้าของ เช่น `yourname+packtooktest@gmail.com` (ต้องมีคำว่า `packtooktest` ในส่วนก่อน @) ไม่ใช่บัญชี Owner หรือลูกค้าที่ใช้งานจริง
2. ยืนยัน Email ของบัญชีทดสอบให้เรียบร้อย ต้องเป็นบัญชี Firebase Auth ที่สร้างภายใน **7 วันล่าสุด**
3. คัดลอก UID ของบัญชีใหม่มาใช้ใน Cloud Shell และให้สิทธิ์ Production Beta:
   ```bash
   cd ~/packtook-production-v621
   git pull --ff-only origin feature/v6.2.3-owner-customer-management
   cd production
   export GOOGLE_CLOUD_PROJECT=packtook-prod-01
   node functions/scripts/manage-beta-user.js grant YOUR_NEW_TEST_UID
   node --check owner-functions/scripts/provision-beta-wallet-test.js
   ```
4. Provision Wallet ให้เฉพาะบัญชีทดสอบ:
   ```bash
   node owner-functions/scripts/provision-beta-wallet-test.js \
     YOUR_NEW_TEST_UID "yourname+packtooktest@gmail.com"
   ```
   เมื่อระบบถามให้ยืนยัน พิมพ์ `CREATE-PROD-TEST-WALLET-YOUR_NEW_TEST_UID` (เปลี่ยนเป็น UID จริง) คำสั่งจะสร้างบัญชี **Starter ทดสอบ**, Credit Wallet **50 เครดิต** และวันหมดอายุ **อีก 30 วัน**, ใส่ marker `internalTestOnly:true`, และ Audit record หนึ่งรายการ
5. เปิด Owner Dashboard → Customer Directory → เลือกบัญชีทดสอบ → กด **จัดการ** → เพิ่มเครดิต **10** แล้วตรวจว่า 50 → 60 ใน Customer App และ Audit Log

## หลักการป้องกัน

- Helper จะปฏิเสธเมื่อ Firebase Project ID ไม่ใช่ `packtook-prod-01` หรือ Email ไม่ตรงกับ Firebase Authentication
- ต้องเป็นบัญชีใหม่ที่ยืนยันอีเมลแล้ว ได้รับ `packtookProductionBeta:true` แต่ **ไม่มีสิทธิ์ Owner/Manager**
- ปฏิเสธบัญชีที่มีประวัติ recordings, billingRequests, ownerChanges, barcodeLocks, duplicateRequests หรือ duplicateApprovals
- หากมีเอกสาร accounts อยู่แล้ว จะยอมรับได้เฉพาะ Free **ที่ยังไม่เคยใช้งาน**, `used=0`, `reserved=0`, ไม่มี Device และไม่มี Wallet เท่านั้น
- ไม่คัดลอกข้อมูล Staging ไม่เชื่อม Omise ไม่สร้าง `billingRequests` และไม่กระทบ Customer Backend
- **บัญชี Starter นี้เป็นบัญชีทดสอบ ไม่ใช่สมาชิกที่ซื้อจริง** เจ้าของระบบต้องไม่นับเข้า KPI ลูกค้าที่ชำระเงินหรือยอดขายจริง (ใน Owner Summary ปัจจุบันบัญชีทดสอบอาจถูกนับรวมในจำนวนสมาชิก Starter/Active จนกว่าจะเพิ่มตัวกรองภายหลัง)
- เมื่อทดสอบเสร็จ ปิด Owner Management ด้วย `bash scripts/set-owner-management.sh packtook-prod-01 disable` และ Deploy Owner Functions เพื่อให้มีผล
- ห้ามทดลองเพิ่มเครดิตให้บัญชี Owner, Free จริง หรือบัญชีลูกค้าที่มีการบันทึกวิดีโออยู่

## ข้อจำกัดของการทดสอบ

การทดสอบบน Production ยังต้องทำเองหลังรันคำสั่ง; การผ่าน Regression Test ของโค้ดไม่ได้เท่ากับทดสอบธุรกรรมจริงบน Firebase ครบทุกกรณี

`ownerManageCustomer` ของ V6.2.3 ใช้ Operation ID ป้องกันการทำซ้ำ แต่กดเพิ่มเครดิตใหม่อีกรอบหลังบันทึกสำเร็จจะเป็น **คำสั่งใหม่และเพิ่มเครดิตอีกครั้งตามปกติ** จึงไม่ใช่วิธีทดสอบ Idempotency ด้วยการกดซ้ำคนละครั้ง ให้ใช้ Audit Log และ Regression Test ที่มีเพื่อยืนยันแทน
