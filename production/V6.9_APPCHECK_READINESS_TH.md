## Step 2 — create/register a score-based public Site Key in Console (manual)

Review the current Firebase instructions:
- [App Check with reCAPTCHA Enterprise — web](https://firebase.google.com/docs/app-check/web/recaptcha-enterprise-provider)
- [Enforce App Check with Cloud Functions callable](https://firebase.google.com/docs/app-check/cloud-functions)
- [Debug environment warnings](https://firebase.google.com/docs/app-check/web/debug-provider)

1. In Google Cloud, select **packtook-prod-01**. Open reCAPTCHA Enterprise (Fraud Defense) and create a **Web, score-based key**. Disable checkbox challenge.
2. Authorize only `packtook-prod-01-app.web.app` for this Customer instance (and any separately approved future custom Customer domain). Do **not** authorize `localhost` or a staging domain on the Production key.
3. In Firebase Console → **Security → App Check → Apps**, locate the **same Customer Web App** as the `app/firebase-v4-config.js` `appId`. Register it using the newly created **public** Enterprise Site Key.
4. Keep the value labelled *Site Key* separate from backend secrets. The Public Site Key is not secret, but never paste an API credential, service account private key, Omise secret, or App Check debug token into this repo or chat.
5. Observe the App Check app registration and monitoring metrics. Consider Firebase's documented TTL and risk threshold; do not enable global App Check enforcement on all existing Beta callables.
6. Only after verified registration, create a separately reviewed commit to set `appCheckSiteKey` in the client config. **Do not change this file now**, because the existing V6.5 fail-closed regression explicitly requires a blank Site Key until launch QA approval.
