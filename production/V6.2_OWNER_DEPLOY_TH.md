# PACKTOOK V6.2 — Production Owner Dashboard

**Scope:** Read-only Owner Analytics + Customer Account Directory for isolated Firebase Production project `packtook-prod-01`. Based on verified Customer V6.1.2. No changes to the working Customer Hosting / existing 12 Credit Functions.

**Status:** Code committed to branch `feature/v6.2-production-owner-dashboard`; **not deployed**, not live-tested. Run the steps below in Cloud Shell.

## 1. Architecture

- Owner URL: https://packtook-prod-01-owner.web.app (after Deploy)
- Customer remains: https://packtook-prod-01-app.web.app
- Staging remains: https://packtook-staging.web.app
- Production Owner Frontend: `production/owner`; layout, logo and eagle mascot copied from Staging Owner; finances explicitly **disabled** because Production is not collecting payments.
- Production Owner Backend: `production/owner-functions` (dedicated Firebase Functions codebase: `owner`; region `asia-southeast1`). Two read-only callables:
  - `ownerAnalyticsSummary`: month-by-month new active accounts, plan segmentation, active/expired/free counts.
  - `ownerAnalyticsCustomers`: paginated 25 per page, canonical Firebase Auth email, plan, status, available credits, reserved credits, account creation, expiry. Returns up to 25.
- The Owner backend is permitted **only** when the verified Firebase ID token contains `packtookPlatformOwner: true`. Firebase `packtookProductionBeta` and customer `admin` are **not** equivalent. Backend verifies exact Production project, verified email and the current Auth user record on every request (including Owner claim and disabled status).
- Production Firestore client rules remain deny-all; Owner Functions Admin SDK reads only `accounts` (and Firebase Authentication user records). No credits/expiration writes, no Omise APIs, no cross-project migrations.
- Customer counts reflect **accounts with Firestore documents** (usually created on first successful usageStatus), not every Firebase Authentication signup. Report limit 1,200 accounts with a `truncated` flag.

## 6. Create and authorize the Owner login

Use a **separate Production Owner Firebase Authentication user**, not a customer account. In Production Firebase Console → Authentication → Users → Add user. Make sure Email/Password provider is enabled. If the account is not verified, sign in once at the Owner site: it will send an email verification link and sign out. Verify the mailbox, then copy its **Production Auth UID**.

**Only after confirming the UID belongs to the intended Production Owner**:

```bash
cd ~/packtook-production-v62/production

export GOOGLE_CLOUD_PROJECT=packtook-prod-01

node owner-functions/scripts/manage-platform-owner.js \
  grant PRODUCTION_OWNER_AUTH_UID
```

Replace `PRODUCTION_OWNER_AUTH_UID` with the exact UID from Production Firebase Authentication.

The helper refuses any other project and refuses unverified accounts; it preserves existing custom claims. After assigning the claim, sign out and sign in again to refresh the ID token.

To revoke access:

```bash
node owner-functions/scripts/manage-platform-owner.js \
  revoke PRODUCTION_OWNER_AUTH_UID
```

Owner Functions additionally query the current Firebase Auth user record on every privileged request, so removing the Owner claim or disabling the account blocks subsequent Owner data reads without relying solely on ID-token refresh.

## 8. Troubleshooting

- `permission-denied`: Owner email not verified or custom claim missing; verify project and re-login.
- `not-found`: Confirm both Owner Functions were deployed to `asia-southeast1`.
- `unavailable` while loading customers: check Owner Function Logs, particularly Firebase Admin Auth `getUsers` permissions. Do not grant broad user-level permissions in frontend; fix the backend service account's minimally required role.
- Empty customers: only accounts with `accounts/{uid}` documents appear (the Customer app creates this on authorized usage).
- Login not sending action emails: verify Authentication Email/Password, email template, authorized Production Owner domain and registered Web App.
- `static isolation checks` fail: you may have cloned the older V6.1 branch instead of `feature/v6.2-production-owner-dashboard`.
