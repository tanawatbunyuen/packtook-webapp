## A. What was added in source

1. \`app/pilot-free.html\` includes a **manually triggered Browser App Check** diagnostic. It calls \`getToken(appCheck,true)\` using the configured reCAPTCHA Enterprise Web provider and only displays a boolean outcome:
   - \`CLIENT APP CHECK TOKEN RECEIVED\` means the Browser SDK got a token. **It does NOT prove the Firebase callable server accepted the token**.
   - \`CLIENT APP CHECK FAILED\` means troubleshoot the browser domain/key, project app registration, adblock, consent or network; do not launch.
   - It **never writes, displays, stores or logs the token itself**. No email, UIDs, passwords or raw cloud identities belong in diagnostics.
   - This page is **source-only and not deployed**. A browser cannot visit it live until a separately authorized Hosting update.
2. \`scripts/v72-live-surfaces-preflight.mjs\` reads **four exact allowlisted URLs** and the already-approved \`publicSignupStatus\` read-only probe. It checks:
   - Owner Hosting + JS + Firebase web project/domain without printing API keys.
   - Marketing/Customer HTTP, Public Signup/Access OFF.
   - V7.2 Pilot page **not unexpectedly present on Production**.
   - Returns \`NO_GO_CONTROLLED_PILOT\` in every case. This is **HTTP-only**, no Owner credentials, no real App Check, no Firebase write.
3. \`scripts/test-v72-live-surfaces-preflight.mjs\` and browser regression mutation tests cover accidental early Pilot publication, mismatched Owner staging config, wrong Public flags and token diagnostics.
4. The existing Owner Dashboard is **not changed**.
