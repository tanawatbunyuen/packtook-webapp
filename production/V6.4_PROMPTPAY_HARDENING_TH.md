# PACKTOOK V6.4 — PromptPay QR Payment Hardening (Omise TEST ONLY)

**Repository branch:** `feature/v6.4-promptpay-payment-hardening`  
**Production Firebase project:** `packtook-prod-01`  
**Status:** committed to GitHub; source-level/mocked Firebase + Omise regression tests pass. **No deployment has been performed by the assistant.**  
**Scope:** Omise **Test QR only**, read-only Owner payment operations, and Customer QR expiry UI. **No Credit Card. No Omise Live payments.**

## What V6.4 adds

### A. Test Payment Backend (isolated `functions:promptpay` codebase)

- On creation, keep the 30-minute expiry request and store the provider-acknowledged QR `expires_at` separately from requested expiry. Do **not** declare QR Failed/Expired based on browser time alone.
- A repeat checkout for an already-linked Charge now calls the existing independent `reconcileCharge` function. Returns correct internal status (Paid/Pending/Failed/Expired/Review), with **no terminal QR image**.
- Successful Paid settles with an atomic Firestore transaction and stores verification evidence: `paymentEvidenceVersion:1`, `providerVerifiedAt`, Charge ID, amount in satang, THB, PromptPay source, Test mode and successful Paid status.
- Failed / Expired from **Omise GET** write terminal time and provider failure code/message, remove the outstanding billing lock, and **do not grant any credits**.
- If an already-settled Paid document is later found to disagree with Omise, set `postSettlementAlert` for Owner review **without automatically removing credits or applying payment a second time**.
- Require the unchanged `skey_test_`, `packtookPaymentTester`, production project guard, verified Omise webhook signature and charge metadata/amount checks. No card or Live path is introduced.

### B. Owner dashboard (`functions:owner` + `hosting:owner`)

- New read-only `ownerPaymentHealth` callable protected by Production Platform Owner Auth claim, checked against the latest Firebase Auth user.
- New menu **ตรวจธุรกรรม QR** with pending QR, QR likely past expiry **but unverified by Omise**, stuck Charge creation, Payment Review, provider discrepancy, Paid missing proof and Paid with verified proof.
- Lists up to 40 flagged requests with Account UID, Request ID, plan, amount and age in minutes. Bounded scan (400 accounts; 25 recent billing records/account). Includes partial-data warning. **Read-only Firestore snapshot, not Omise/bank reconciliation.**
- Updated Revenue mode classification: Omise TEST Charges with normal `chrg_...` IDs are recognized as Test **only when stored trusted Test/PromptPay verification evidence is present**. Legacy `chrg_test_` records remain supported. Never infer Live revenue from missing mode metadata.

### C. Customer App (`hosting:app`)

- Displays the **Omise-confirmed** QR expiration time in Bangkok timezone when provided. Local time can show that QR is overdue but cannot mark the Charge as failed.
- Keeps V6.3.2 behavior: QR disappears and a success/failure state replaces it **only after Backend confirms a terminal status**; pending QR is polled while the active Packages tab is visible.
- Recording, Camera, Barcode, local .webm, Dashboard and credit deduction Functions are unchanged.

## Deployment — 4 isolated steps

**Before starting:** User already deployed V6.3.2, and the Omise TEST secrets are already configured. Do **not** recreate or paste secrets. Do **not** run `scripts/prepare-promptpay.sh`, because it resets `PACKTOOK_PROMPTPAY_TEST_ENABLED` to `false` locally.

### 1. Switch Cloud Shell to V6.4

```bash
cd ~/packtook-production-v621

git fetch origin feature/v6.4-promptpay-payment-hardening
git switch feature/v6.4-promptpay-payment-hardening 2>/dev/null || \
  git switch -c feature/v6.4-promptpay-payment-hardening FETCH_HEAD
git pull --ff-only origin feature/v6.4-promptpay-payment-hardening

cd production
git branch --show-current

# Read-only verification and mocked tests (no payment, no Firebase mutation)
node scripts/verify.mjs packtook-prod-01
node scripts/test-promptpay.mjs
node scripts/test-owner.mjs
node scripts/test-owner-charts.mjs
node scripts/test-owner-management.mjs
node scripts/test-owner-management-ui.mjs
node scripts/test-qr-lifecycle.mjs
node scripts/test-customer-ui.mjs
```

Expected key logs:

```text
PACKTOOK V6.4 PromptPay Test Payment Hardening checks: PASS for packtook-prod-01
PASS: V6.4 Omise QR Test Paid/Failed/Expired, Webhook signature, evidence, idempotency, credit safety and alert
PASS: V6.4 Owner analytics, QR health, payment review, evidence and permission isolation
```

### 2. Deploy ONLY the Payment Functions (not Beta or Staging)

```bash
cat payment-functions/.env.packtook-prod-01
bash scripts/deploy-promptpay-functions.sh packtook-prod-01
```

The local env must show `PACKTOOK_PRODUCTION_PROJECT_ID=packtook-prod-01`. If the Test flag is currently `true`, it will be **preserved**: this deployment script does not change the flag.

When prompted, type `DEPLOY-PROD-QR-TEST-FUNCTIONS`.

### 3. Deploy ONLY Owner Functions, then Owner Hosting

```bash
# Preserve your existing production owner-functions/.env.packtook-prod-01.
# Do not run prepare-owner.sh if it would overwrite prior management settings.
bash scripts/deploy-owner-functions.sh packtook-prod-01
bash scripts/deploy-owner-hosting.sh packtook-prod-01
```

Type `DEPLOY-PROD-OWNER-FUNCTIONS` and `DEPLOY-PROD-OWNER-HOSTING` at the respective prompts. `functions:owner` now contains **7** functions (6 existing + `ownerPaymentHealth`).

Open https://packtook-prod-01-owner.web.app/ → **ตรวจธุรกรรม QR**. Press Ctrl+Shift+R if the previous frontend is cached. Must show read-only alerts and a caveat that the scan is **not bank/Omise reconciliation**.

### 4. Deploy ONLY Customer Hosting

```bash
bash scripts/deploy-promptpay-customer.sh packtook-prod-01
```

Confirm `DEPLOY-PROD-QR-TEST-CUSTOMER`.

Open https://packtook-prod-01-app.web.app/ → Packages. Refresh browser cache and check `app.js?v=6.4.0`. The QR expiry label appears when Omise returns `expires_at`.

**Scope isolation:** These scripts do **not** redeploy the 12 established Customer Recording Functions (`functions:beta`), Firestore rules, Marketing Hosting or Staging.

## V6.4 Test acceptance

- [ ] Existing Customer Login, Recording Start/Stop, local video file, Dashboard and Credit 1/video behavior remain unchanged.
- [ ] Omise Test Starter QR is shown; Paid not granted while provider status Pending.
- [ ] The QR expiry time is shown if included in the Omise charge response. A browser-past time does not mark Paid/Failed by itself.
- [ ] Omise Test "Mark as Successful" (or existing test Charge) is independently verified; one and only one plan/credit grant.
- [ ] Clicking Check Status repeatedly does not grant credits again; a retry of QR creation does not create another Charge for the same linked request.
- [ ] An Omise Test Failed/Expired Charge releases billing lock and does not grant credits; failure evidence appears in backend.
- [ ] Paid history and Owner Test revenue agree as **ledger entries**, not real money; Test does not appear in Live.
- [ ] Owner **ตรวจธุรกรรม QR** displays pending/stale/review alerts and bounded-scan caveat.
- [ ] Owner with no `packtookPlatformOwner` claim cannot access health report.
- [ ] No credit card or Live Omise option appears; regular Beta customers without `packtookPaymentTester` cannot purchase Test QR.
- [ ] Any Paid charge later inconsistent with provider requires review; never claw back credits automatically.

### Cautions

1. The Owner health report is read-only and only reads **recent Firestore billingRequests**. `payment_pending` older than expiry means **recheck the provider**, not "payment expired". For a stuck `creating_charge` ticket, the customer should use existing **กู้คืน Charge**; do not manually delete it or create another unverified charge.
2. Test Charges can change the Production **test account's** credit wallet even without real money. Use only dedicated QR Tester accounts, not active packing accounts.
3. Omise confirms PromptPay `expires_at` support, but the timestamp should be taken from the API response when available; expiry by clock does not replace provider confirmation.
4. No live payments until additional end-to-end, accounting, refund/incident-response and operational authorization reviews.

## Emergency stop / rollback

To stop **new Test checkout and status settlement**, explicitly turn off the feature gate and redeploy only the QR Functions:

```bash
bash scripts/set-promptpay-test.sh packtook-prod-01 disable
bash scripts/deploy-promptpay-functions.sh packtook-prod-01
```

This stops all Test payment API flows and Webhook handling until the gate is re-enabled. **Note**: disabling the gate also stops manual status recovery; keep records for later reconciliation.

To rollback the full feature code, deploy the older V6.3.2 branch using its guarded scripts for Payment/Owner/Customer/Owner Hosting. Preserve Firebase secrets and existing local environment files. Do not mix Staging configs.
