IAM metadata alone cannot establish that the live function can retrieve secret bytes. ## Least privilege review

- Do **not** publish full \`get-iam-policy\` outputs or function service account names in a public PR. The script intentionally returns only counts and boolean flags.
- \`roles/secretmanager.secretAccessor\` granted **at project level** can access more secrets than intended and requires owner review; a secret-scoped direct grant is preferred for the identified runtime account.
- Conditional bindings and inherited policies require separate approval; the audit does not claim to resolve all effective access.
- \`allUsers\` or \`allAuthenticatedUsers\` grants with sensitive roles are flagged.
- Review secret rotation, version pinning, lifecycle/retention, restricted production scopes, service account reuse and alerting.
- The actual secret **must never** be pasted into chats, GitHub, Cloud Shell history or debug logs.
