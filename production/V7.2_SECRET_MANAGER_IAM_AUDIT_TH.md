## What is inspected — read-only

| Check | Production resource | Expected evidence |
|---|---|---|
| Source | \`production/functions/index.js\` | SecretParam exists, all 4 callables bind it, runtime accessor uses \`.value()\` |
| Secret resource | \`gcloud secrets describe\` | Exists; metadata only, not payload |
| Versions | \`gcloud secrets versions list\` | At least one \`ENABLED\` version |
| Secret-specific policy | \`gcloud secrets get-iam-policy\` | Readable; runtime principal gets least-privilege \`roles/secretmanager.secretAccessor\` at the **secret** scope, unconditional or reviewed separately if conditional |
| Project policy | \`gcloud projects get-iam-policy\` | Detect project-wide grants; broad grants need owner review |
| Deployed functions | Gen2 \`gcloud functions describe\` | \`publicSignupStatus\` and \`completeFreeSignup\` deployed; runtime Service Account metadata available; \`serviceConfig.secretEnvironmentVariables\` actually binds expected Secret |
| Pilot callables | Gen2 \`gcloud functions describe\` | Expected \`NOT_FOUND\` while no Pilot deployment is approved. Unexpected deployment is a blocker |

The script reports \`metadataInspectionComplete\` and \`metadataFindingsPass\` separately. Even when \`metadataFindingsPass:true\`, the result is STILL:
\`\`\`json
{
  "readyForPilot": false,
  "readyForPublic": false,
  "decision": "NO_GO_CONTROLLED_PILOT"
}
\`\`\`

**Why:** A secret-scoped IAM grant is necessary evidence of intended authorization, but the effective permission can be altered by hierarchical IAM policies, conditions, policy-deny, service account impersonation, organization restrictions and the deployed revision. IAM metadata alone cannot establish that the live function can retrieve secret bytes. The first successful **real runtime** access and validation must occur only in an independently authorized, tightly scoped release rehearsal, with **no payload logging**.

If \`metadataFindingsPass:false\`, inspect \`blockers\` and the \`inspectionError\` fields. Exit code 2 is intentional for absent or unverified critical metadata. Do not assume a Not Found Pilot callable is an error: it is expected for this unapproved, source-only V7.2 release.

## Least privilege review

- Do **not** publish full \`get-iam-policy\` outputs or function service account names in a public PR. The script intentionally returns only counts and boolean flags.
- \`roles/secretmanager.secretAccessor\` granted **at project level** can access more secrets than intended and requires owner review; a secret-scoped direct grant is preferred for the identified runtime account.
- Conditional bindings and inherited policies require separate approval; the audit does not claim to resolve all effective access.
- \`allUsers\` or \`allAuthenticatedUsers\` grants with sensitive roles are flagged.
- Review secret rotation, version pinning, lifecycle/retention, restricted production scopes, service account reuse and alerting.
- The actual secret **must never** be pasted into chats, GitHub, Cloud Shell history or debug logs.

## No-Go checklist after audit

**Metadata can be checked now.** The following remain independent required blockers: verified runtime Secret access to the intended function revision, real signed Browser App Check and callable acceptance, Cloud Monitoring alerts and Billing notifications, Firebase Auth/email-abuse protections, PDPA Terms/Privacy retention approval, a tested runtime Pilot kill-switch and rollback, and explicit owner go/no-go authorization.
