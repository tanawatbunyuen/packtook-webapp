# PACKTOOK V6.1 — Production Customer Beta (ภาษาไทย)

**GitHub branch:** `feature/v6.1-production-customer-beta`  
**Target:** `packtook-prod-01` ONLY. **Staging remains `packtook-staging`.**  
**สถานะ:** โค้ดพร้อมจัดเตรียมและ Deploy แบบแยกส่วน แต่ยัง **ไม่ได้ Deploy / ทดสอบกับกล้องจริงและ Firebase Production โดยผู้พัฒนา** ไม่มีการรับชำระเงินจริง

## สิ่งที่ย้ายจาก Staging

- หน้า Login, Packing, Dashboard, Packages, Users, Help ใช้ HTML/CSS/JS จาก `firebase-staging` เพื่อให้ UX/UI เหมือนเดิม
- `logo.svg` / `mascot-eagle.svg` ใช้ไฟล์เดียวกับ Staging; หน้า Marketing ก็ใช้โลโก้/มาสคอตนี้
- `login-background.png` ย้ายจากราก Repository ใน Cloud Shell ระหว่าง Prepare (Binary ไม่เผยแพร่บน GitHub เพิ่ม)
- ฟีเจอร์กล้อง Preview, Fullscreen, 720p/1080p, Barcode Start/Stop, Local Video, IndexedDB History, Recovery, Device, Performance Monitor ใช้โค้ด Staging ที่ผ่านการปรับ Environment
- 12 Callable Functions ฝั่ง Production เขียนมาจาก core Staging แต่เพิ่ม **Server-side custom claim `packtookProductionBeta===true`** และ Email Verified สำหรับทุก endpoint; แยก Codebase `beta`; ไม่มี Omise secrets หรือ Payment exports
- Packages แสดงข้อมูล Read-only; การซื้อแพ็กเกจ/การชำระเงินถูกปิดแม้มีใครเรียก API โดยตรง
- Owner Site ยังคงเป็น Holding Page (V6.2 จึงค่อยเปิดสิทธิ์ Owner Production หลังทดสอบจริง)

### Important: Production Billing is CLOSED

No Omise Live or Test payment API in Production code. The client plan purchase controls are disabled, with server purchase API intentionally missing. Avoid deploying `firebase-staging/functions/index.js` or staging web config into Production.

## 0. Firebase Console prerequisites

1. Verify the new Firebase project ID is exactly `packtook-prod-01` (already created for V6.0).
2. Enable **Blaze** billing plan if deploying Cloud Functions; set Cloud Billing budget alerts (not a hard spending cap).
3. Create the **Production Cloud Firestore** database with the chosen region. Do not copy test accounts or collections from Staging. Server Admin SDK needs Firestore even when client rules deny all.
4. Authentication → Sign-in method → enable **Email/Password** for testing; under Authentication Settings / User Actions, **disable end-user self signup and delete** where supported. Beta users will be created/administered manually. Firebase Authentication normally allows client self-signup by default. Source: https://firebase.google.com/docs/auth/users.
5. Register **one Firebase Web App** in the Production project. Use its Web App ID (format `1:…:web:…`) in the next step. Do not use staging's Firebase App ID or `apiKey`.
6. Authentication → Settings → Authorized domains: confirm the Production Customer site `packtook-prod-01-app.web.app` is allowed. Add `app.packtook.com` only when you own and map that custom domain.

## 1. Clone V6.1 without disturbing V6.0 and Staging

```bash
cd ~
git clone --depth 1 --branch feature/v6.1-production-customer-beta \
  https://github.com/tanawatbunyuen/packtook-webapp.git \
  packtook-production-v61
cd ~/packtook-production-v61/production

# Copy only the already confirmed PRODUCTION Hosting target mappings.
cp ~/packtook-production-v6/production/.firebaserc ./.firebaserc

node scripts/verify.mjs packtook-prod-01
```

**Do not** use `~/packtook-webapp` (staging repository) for Production deployment. Every Firebase CLI command below uses `--project packtook-prod-01`.

## 2. Generate Production Firebase Web config

Get Web App ID from Firebase Console > Project Settings > Your apps, or:

```bash
firebase apps:list --project packtook-prod-01
```

Then replace the placeholder:

```bash
PROD_ID="packtook-prod-01"
WEB_APP_ID="PASTE_PRODUCTION_WEB_APP_ID"

firebase apps:sdkconfig WEB "$WEB_APP_ID" \
  --project "$PROD_ID" \
  -o /tmp/packtook-prod-sdk.json

node scripts/configure-web.mjs "$PROD_ID" /tmp/packtook-prod-sdk.json
```

This creates `production/app/firebase-v4-config.js` only on your Cloud Shell. It verifies project ID and Auth domain; Git ignores this file. The Firebase Web SDK config is public client configuration, not an Admin credential. Do not paste service-account secrets or Omise API keys here.

## 3. Prepare UI and Functions (still no deployment)

```bash
bash scripts/prepare-beta.sh "$PROD_ID"
```

This copies the original login background, checks JavaScript and Firebase config, creates the non-secret `functions/.env.packtook-prod-01`, and runs `npm install` for Functions. All operations remain in the Production V6.1 folder.

## 4. Lock the Production Firestore database (one time)

After Firestore has been created, keep the **client rules denying all direct reads/writes** for Beta. Recording/wallet endpoints use authenticated Cloud Functions with Admin SDK:

```bash
bash scripts/lock-firestore.sh "$PROD_ID"
```

Type `LOCK-PROD-DATABASE` when prompted. **Never run this against Staging or an already-active customer Production service.**

## 5. Deploy Core Beta Functions to Production

```bash
bash scripts/deploy-beta-functions.sh "$PROD_ID"
```

Type `DEPLOY-PROD-BETA-FUNCTIONS` when asked. It deploys **only** 12 `beta` codebase callables, in two groups, with no paid payment functions.

The Cloud Functions region is `asia-southeast1` just like Staging. The Firebase CLI loads the environment file `functions/.env.packtook-prod-01` into this Production codebase.

## 6. Deploy Customer-only UI and optional Marketing branding

```bash
bash scripts/deploy-beta-customer.sh "$PROD_ID"
```

Type `DEPLOY-PROD-CUSTOMER-BETA`. This updates only `packtook-prod-01-app.web.app`. The Owner page, Marketing, and Staging remain untouched.

To publish the Staging-matched logo/mascot on Marketing as a separate step:

```bash
bash scripts/deploy-beta-marketing.sh "$PROD_ID"
```

Type `DEPLOY-PROD-MARKETING`. This updates only `packtook-prod-01.web.app`.

## 7. Provision a Production test login (after website deploy)

1. Firebase Console (Production) → Authentication → Users → Add user. Give this user a strong password; **do not add this user to the Staging project**.
2. Open `https://packtook-prod-01-app.web.app`. If this account has not verified its email, try logging in; the portal will send an Email Verification link and sign out. Complete verification from the user's mailbox.
3. Copy its **Production Firebase Auth UID** from Console.
4. Grant Beta access through the trusted Cloud Shell/Admin SDK (without using your Firebase web API key):

```bash
cd ~/packtook-production-v61/production
export GOOGLE_CLOUD_PROJECT=packtook-prod-01
node functions/scripts/manage-beta-user.js grant PRODUCTION_TEST_USER_UID
```

The script rejects unverified emails and merges existing custom claims. Sign out/in to refresh token. To revoke access:

```bash
node functions/scripts/manage-beta-user.js revoke PRODUCTION_TEST_USER_UID
```

**Never assign `packtookProductionBeta` to everyone or bypass server Auth.** Beta client membership is determined by the server-verified custom claim, not by emails entered in the browser.

## 8. Test checklist before inviting external customers

1. Login succeeds only for verified Production user with `packtookProductionBeta=true`. Non-Beta user must be denied the 12 callable functions.
2. Try a new Barcode on a Chrome/Edge desktop, camera enabled, folder selected, default 720p. Scan twice to Stop; wait for file saved/verified.
3. Verify local WebM actually plays, image is not black, exactly one credit is counted, and video appears in Dashboard search.
4. Test duplicate Barcode approval, device registration/transfer, camera full screen, quality selection and indexed history pagination.
5. Test 50–100 orders across a session, at least 30 minutes continuous recording, slow disk, network disconnection after reservation, browser crash/reopen and Pending Credit recovery. **This reliability suite remains required before public launch.**
6. In Packages: every paid purchase button should be disabled. No Omise QR or live charge should be possible; backend has no payment exports.
7. Staging `https://packtook-staging.web.app/` remains unchanged, with separate Auth accounts and Firestore.
8. Production Owner site remains a holding page; no customer cross-tenant data access.
9. Monitor Firebase billing, Function errors and Firestore usage. Confirm the camera permission header is `camera=(self)`.

## Troubleshooting

- **Missing SDK config:** ensure you registered a WEB app in Production and ran `scripts/configure-web.mjs` on the matching output.
- **`permission-denied` after login:** verify Production UID, email verification and custom claim; sign out and in again.
- **`failed-precondition` at Backend:** check `functions/.env.packtook-prod-01` and Cloud Functions deployment logs. Do not disable the project guard.
- **Camera blocked:** ensure you used V6.1 firebase.json with `camera=(self)`; allow camera in the browser, choose Chrome/Edge.
- **Functions project missing Firestore:** create a Production Firestore database, ensure Blaze plan is active, deploy Rules before functions.
- **No Internet on Cloud Shell / SDK CLI unsupported:** do not paste any secret keys into chat. Use Firebase Console's public WEB SDK config to construct a JSON file locally and then run the config generator.
- **Need rollback:** Firebase Hosting Release History can roll back the Production Customer deployment; Functions changes require controlled code rollback. Staging deployment is independent.
