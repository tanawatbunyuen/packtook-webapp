## 5. Rollback Procedure — reviewed plan only, never auto-run
A Generation-2 Cloud Function's underlying Cloud Run service can route traffic to a previously deployed revision. Google Cloud documents `gcloud run services update-traffic SERVICE --to-revisions REVISION=100` as a rollback mechanism. This is a **Production write**, must be separately approved and can route requests immediately without re-running deployment health checks; in-flight requests may finish on the previous/newer revision.

**Before any separately approved rollout:** capture a durable immutable per-function baseline: function export, Cloud Run service name, exact currently SERVING revision, container image reference/digest, current traffic split, deployment source SHA, environment/service-identity metadata, and a Beta smoke PASS. Check the revision still exists. A `functions describe` revision field alone is not sufficient: use Cloud Run traffic as source of truth for current serving revision.

**Incident trigger:** Beta authentication failures, device/credit incorrectness, video-save failures, elevated Cloud Run errors, Public status changed, unexpected Pilot access or unapproved identity/traffic drift.
1. STOP new deploy steps, keep Public/Pilot OFF, capture affected services and current traffic state.
2. On owner approval, select ONLY one affected Cloud Run service and validate the exact known-good revision exists and image still accessible. Example TEMPLATE — DO NOT RUN IN THIS REVIEW:
```bash
# PRODUCTION WRITE — ONLY WITH SEPARATE OWNER ROLLBACK APPROVAL:
# gcloud run services update-traffic SERVICE \
#   --project=packtook-prod-01 --region=asia-southeast1 \
#   --to-revisions KNOWN_GOOD_REVISION=100
```
3. Immediately verify revision traffic, function HTTP, Beta functional smoke, local save and credit idempotence; if rollback cannot restore healthy state, escalate and block Pilot. Repeat separately for each affected function; **never automatically roll all twelve back**.
4. Document any Firebase CLI reconciliation risk. Future Firebase function deploys may change service traffic routing, and a rollback of traffic alone does not revert Firestore schema, Auth claims, Secret versions, external dependencies or account changes.

**Safer dry rehearsal:** perform rollback-routing rehearsal in an isolated non-production Cloud Run service with two harmless revisions and test that requests route to known previous revision; no Production modifications. This rehearsal requires a separate approved sandbox and is not performed here.
